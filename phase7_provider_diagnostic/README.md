# Provider refusal diagnostics

This is a diagnostic-only revision of the existing Phase 7 provider executor. The original executor, collector, packet parser, runtime checker, sampler and completed observations remain unchanged.

The new executor keeps the same five-key collector reply and all existing process controls. Its separate `last_diagnostic` snapshot reports only finite error/phase labels, a child exit status when actually observed, bounded byte counts when supervision completed, a conservative fixed stderr classification, and client closure state. The added executor diagnostic never publishes raw service replies, arbitrary error text, owner names, server references or their hashes. The unchanged runtime record may still contain its previously approved sanitized provider-evidence digests when collection succeeds. An exact no-owner text classification is a reported message, not independently proven provider absence. Missing or incomplete observations remain null.

The new job entry reuses the existing sampler, collector, packet parser and runtime checker, binds all module bytes by SHA-256, and adds the diagnostic snapshot to the public result. Operative refusal and all authority/alignment flags remain unchanged. If runtime refuses before any executor call, no diagnostic is manufactured. An unresolved client still leaves the owner monitored until the existing process-group timeout; that termination is containment, not proof of reaping.

The manual workflow requires the exact repository, public visibility, main branch, approved commit and first run attempt. It uses pinned read-only checkout; observation remains under `timeout --signal=KILL 20s`, with a two-minute job limit. The existing limits remain: at most four modes-zero kernel reads and six fixed reads of the existing timesyncd service; 15-second runtime, 10-second collector, maximum four-second executor call, existing cleanup reserves and output caps. There is no retry, alternative provider, service activation/install/restart, new NTP request, target probe, clock change or VPS action.

One separately approved diagnostic job can clarify its own failure or collect its own capability evidence. It cannot qualify a later runner, establish cross-machine alignment, refresh an old deadline or open the gate. Even if the existing reads succeed, Phase 7 remains blocked pending applicable timing and live gate evidence.
